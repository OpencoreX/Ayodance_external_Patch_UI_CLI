# Ayodance LAN Room Sync Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a tested LAN HOST/CLIENT room synchronization system with SOLO mode, quorum-ready Play authorization, compact tabbed UI, and documented image-detection extension points.

**Architecture:** Protocol and round state are framework-only classes independent from WinForms and sockets. A TCP transport carries newline-delimited JSON while UDP advertises HOST sessions; a coordinator maps transport events into deterministic round transitions. Form1 consumes coordinator snapshots through UI-context progress callbacks and keeps image matching/clicking behind placeholders.

**Tech Stack:** C# 7.3-compatible syntax, .NET Framework 4.8, WinForms, TCP/UDP sockets, DataContractJsonSerializer, BackgroundWorker, CancellationToken, legacy MSBuild

## Global Constraints

- Preserve existing Fast Scan, PATCH, REVERT, START loop, and bundled AyodanceID resources.
- Build x64 with `Prefer32Bit=false`.
- Support quorum 2, 3, or 5 total instances including HOST.
- Identify instances as `MachineName + LDPlayer instance name`; never use PID as stable identity.
- Keep socket and worker threads away from WinForms controls.
- Do not add NuGet dependencies or Git commits.
- Keep image matching and clicking as safe no-op extension points for later work.
